# 作品集案例：回測結果診斷互動小 app（可嵌入個人網站）

> 目標角色：證券數位產品企劃（重視 AI 投資產品規格、跨 IT 協作、採用證據）

## 1) 問題是什麼

回測數字「看起來漂亮」不代表可上線。常見落差是：

- 沒有回答「賺的是行情還是策略」。
- 成本敏感度被忽略，真實交易摩擦一加就失效。
- 訊號驗證、帳本對帳、資料完整性被混成一句「都測過」。
- 輸出常是靜態圖，難以在面試或作品集裡互動說明判斷過程。

## 2) 這個小 app 幫誰

- **投資研究者／產品企劃**：快速看風險證據，而不是只看績效排名。
- **網站訪客／面試官**：不用開 Python 環境，也能互動檢查關鍵假設。

## 3) 我實作了什麼

### A. 可攜式互動 app（純靜態）

- 輸出 `index.html + app.js + styles.css + data.json`。
- 可直接 iframe 到個人網站，無後端、無登入、無 API key。
- 手機寬度可用（窄版控制列 + 圖表 + finding detail）。

### B. 證據導向診斷引擎（後端）

- 固定成交重播（固定 trades + Open/Close）：
  - 支援成本/滑價調整後即時計算新淨值與回撤。
  - 明確標示「不是重新選股/再優化」。
- finding 分級：`pass / fail / insufficient / not_applicable`。
- 每個 finding 都有：證據、嚴重度、影響、下一步實驗。

### C. Shioaji 僅讀邊界

- 加入**離線 quote fixture**格式與檢查器（bid/ask、spread、lot）。
- 明確標示：雲端環境未驗證即時帳號連線（`connectivity_verified=false`）。
- 不做登入 UI、不碰憑證、不送真單。

## 4) 怎麼運作（流程）

1. `run_research` 跑既有策略/成本/benchmark/WF 管線。  
2. 產生診斷資料（findings + 重播輸入 + provenance）。  
3. `build_portfolio_bundle` 輸出靜態包。  
4. 網站端用 `data.json` 即時重播成本敏感度並更新圖表。  

## 5) 驗證結果（已量化）

- 單元測試：`tests/test_portfolio_app.py`，含：
  - benchmark 優/劣判定
  - 零成交（insufficient）
  - 成本壓力檢查
  - 缺資料／缺證據標記
  - Shioaji fixture round-trip
  - 靜態 bundle 產物驗證
  - 成本控制改變曲線
- 全專案測試：`161 passed, 10 skipped`
- 互動手測證據：
  - 桌機互動錄影（修改成本、重播、切 finding）
  - 手機窄版互動錄影
  - 桌機/手機截圖

## 6) 取捨與限制（誠實揭露）

- 成本滑桿是「固定成交重播」，**不是**完整策略再訓練。
- Nautilus 對帳是獨立帳本重播，不是獨立訊號生成證明。
- Shioaji 在此只驗證資料格式與執行假設，未在雲端驗證真帳號可連。
- 沒有宣稱未量測的商業成果（例如留存、報酬保證、實際獲利）。

## 7) 下一步

- 若有本機 Mac + Shioaji 帳號：補「讀即時 quote → 匯出 fixture → 匯入 app」的實測證據。
- 增加「完整重跑」按鈕串接 CLI 任務（明確和固定重播分流）。
- 加入交易日集中度與 regime 分段比較的視覺化。

## 8) 一個真實 issue-to-fix 例子（產品判斷）

**問題**：零成交案例一開始在研究流程直接報錯（淨值點數不足），前端只看到失敗，無法分辨是策略無交易還是系統壞掉。  
**修正**：在診斷層改成 `insufficient evidence`，保留可讀訊息與下一步（延長區間或調整觸發條件）。  
**價值**：避免把「證據不足」誤判成「策略失敗」，也避免錯誤成功感。
